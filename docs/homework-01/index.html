01 / The exercise

Private scalar → public point

The professor’s Homework 01 statement asks for an original implementation of Q = kG on y² = x³ + 7 (mod 17), displaying every intermediate multiple and exploring its statistical properties. Here k is the private scalar, G the base point, and Q the resulting point.

The specified example uses G = (1, 5) and k = 6. The calculation below gives Q = (5, 8). Multiplication means adding the point repeatedly; multiplying its two coordinates by six would give the wrong operation.

Educational example only. This tiny curve offers no practical security, and its output is a TOY PUBLIC KEY. Ordinary Ethereum accounts use secp256k1, as identified in the assignment; this page does not derive Ethereum keys or addresses. Ethereum’s account documentation explains the account context.

02 / The mathematics

Addition in a finite field

All coordinates are residues 0 through 16 in F17. The parameters are a = 0, b = 7, p = 17. A finite point satisfies the curve equation; the extra identity O has no affine coordinates. Negation sends (x, y) to (x, −y mod p).

For P = (x₁, y₁) and R = (x₂, y₂), the affine group law is:

Distinct x-values: λ = (y₂ − y₁)(x₂ − x₁)−1

Doubling, y₁ ≠ 0: λ = (3x₁² + a)(2y₁)−1

x₃ = λ² − x₁ − x₂
y₃ = λ(x₁ − x₃) − y₁

Every operation is modulo p.

The inverse d−1 solves dd−1 ≡ 1 (mod p). Extended Euclid finds integers u, v with ud + vp = 1, so u mod p is the inverse. Division therefore means multiplication by an inverse.

P + O = P; inverse points sum to O. Doubling with y = 0 also gives O. These cases precede inversion. The formulas and conventions follow RFC 6090, §§2–3.

A worked first addition

For 2G, 10−1 ≡ 12 because 10 × 12 ≡ 1 (mod 17). Thus λ ≡ 3 × 12 ≡ 2, x₃ ≡ 2² − 2 ≡ 2, and y₃ ≡ 2(1 − 2) − 5 ≡ 10. Hence 2G = (2, 10).

The order n is the first positive multiple giving O. For this G, n = 9: the sequence contains eight finite points, then O, then G again. Consequently (k + n)G = kG. The private-key example uses 1 ≤ k < n; the mathematical algorithm also accepts zero and larger nonnegative scalars.

04 / Exhaustive exploration

Patterns, with an explanation

This is a complete enumeration, not random sampling. For a base of order n, the scalars 1 through n − 1 visit each nonidentity point of its cyclic subgroup exactly once. Equal weight on these scalars is uniform over those points; their individual coordinates need not be uniform over F17.

The default subgroup contains 9 of the full curve’s 18 elements, including O.

Inverse pairs (x, y) and (x, 17 − y) share x. For the default G, x = 1, 2, 5, 12 each occurs twice; y = 1, 5, 7, 8, 9, 10, 12, 16 each occurs once. These repetitions follow from the group structure.

Five-bit coordinates

The encoding is x || y: two unsigned five-bit values, most significant bit first, concatenated into ten bits. For example (1, 5) becomes 00001 00101. A space is shown only for readability.

Input–output relationships

The map is deterministic and periodic, with period n. The integer coordinates can rise, fall, or repeat as k increases. Pearson’s r measures only linear association in the chosen numeric representation:

r(k, x)
r(k, y)

For the default G, r(k, x) = 0 by symmetry and r(k, y) ≈ 0.298. Zero correlation does not imply independence: k determines the entire point. Relabeling residues or choosing a different generator can change numerical correlation without changing the underlying group.

Neighboring scalars: changed output bits

Hamming distance counts differing positions in the ten-bit coordinate encoding for kG and (k + 1)G. Both scalars must be valid: there is no comparison through O or wraparound to k = 1.

No neighboring pair exists in this one-scalar domain.

The default distances are 6, 5, 3, 2, 4, 7, 5. Adding one to k can flip several input bits. These comparisons therefore do not test the classical single-input-bit avalanche criterion, and they do not make scalar multiplication a hash function.

What changing G reveals

G = (2, 10) = 2(1, 5) generates the same order-9 subgroup because 2 and 9 are coprime. It permutes the output order, keeping coordinate and bit frequencies unchanged while changing scalar relationships and neighboring comparisons. In contrast, (5, 9) has order 3, (3, 0) has order 2, and (6, 6) has order 18. Those choices change the dataset itself.

These are exact descriptions of small finite sets, with no sampling uncertainty within each experiment. Their small size and chosen representation prevent conclusions about large cryptographic groups, randomness, or resistance to attack.

05 / Original code, checked

Implementation & verification

The pure mathematical module contains no DOM code. The interface module validates textual input and renders with safe DOM methods. ES modules supply strict-mode semantics. All calculations and SVG marks use standard JavaScript and native browser APIs.

The bounded core accepts prime 5 ≤ p ≤ 997, safe-integer a and b reduced modulo p, and canonical coordinates. It rejects singular curves, composite moduli, and invalid points. Scalars are integers 0–10,000; the cap keeps repeated addition manageable. Its largest field intermediate is below 4 × 10⁹, within exact Number arithmetic. Only Pearson correlation uses approximate floating-point arithmetic. O is represented consistently as null.

Modular inverse

Each Euclidean step preserves a coefficient of the original denominator. A final gcd of one makes that coefficient its inverse; zero or other noninvertible inputs are rejected.

Point addition and doubling

The identity and inverse cases come first. The remaining slope uses either the distinct-point numerator or the doubling numerator, then the same coordinate formulas. Doubling delegates to this one group law.

Repeated addition

Starting at O, each iteration adds G and stores the result. Thus iteration j produces jG. The scalar result is the last stored point; zero iterations give O. Time and stored demonstration steps both grow linearly with k.

A descriptive statistic

Pearson’s r divides the sum of centered products by the square root of the two centered sums of squares. Fewer than two observations or a constant coordinate returns null, displayed as an explanation.

06 / Interpretation

Structure is not security evidence

The subgroup explains coordinate repetition, inverse symmetry, and periodicity. Within the valid scalar domain, every public point is distinct, even when x repeats. The toy discrete logarithm is trivial: at most 17 candidate scalars recover a public point for any selectable base. Real ECC instead requires suitable large groups and parameters; coordinate histograms cannot establish that hardness. See RFC 6090, §10.1.

Elliptic-curve scalar multiplication and cryptographic hashing
AspectScalar multiplicationCryptographic hash
Input → outputA scalar modulo n → a group pointA message → a fixed-length digest
Structure(k + ℓ)G = kG + ℓG; periodic modulo nNo corresponding elliptic-curve group law
Security goalHard discrete logarithms in suitable groups; used in public-key schemes and signaturesPreimage, second-preimage, and collision resistance
Changed bitsThese adjacent-scalar comparisons are illustrative onlySingle-input-bit avalanche analysis is a relevant design measure

Both operations are deterministic and can participate in one-way constructions, but their domains, algebra, and security questions differ. In the canonical scalar range there are no repeated points; outside it, k and k + n coincide by design. This periodicity is not a hash collision claim.
